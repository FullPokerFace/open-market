Earnings notifications.

Signed-in visitors pick the companies they follow and get an email from notifications@<domain> each morning and evening when one of them reports. Mail goes through Resend on a sending subdomain, so the Zoho inbox on the main domain keeps working. Sign-in is a magic link sent through the same Resend setup, so there are no passwords. Follows are stored in MongoDB next to the user, because watchlists today live only in the browser (ticker-lists.js, localStorage) and a cron job can't read them. Two daily Vercel Cron jobs build one digest email per user, never one email per ticker, and log each one so a retry never sends twice.

Build order

  2. 2 Magic-link sign-in
  3. 3 Follows stored on the server
  4. 4 Bell toggle per ticker
  5. 5 Digest email + morning/evening cron
  6. 6 Unsubscribe, bounces, launch checks

What was missing

  • Watchlists are browser-only: merge them on sign-in
  • One-click unsubscribe (Gmail/Yahoo rules)
  • Bounce and complaint handling
  • Send log so nobody gets the same email twice
  • Earnings dates move: tell people about changes
  • Cron times are UTC; ET shifts with daylight saving
  • Protecting the cron route and sign-in from abuse

The real constraint

Resend's free plan allows 100 emails a day and 3,000 a month. With two digests a day that's about 50 active users, and magic-link emails count too. Send only when a followed company has news, and plan for the $20/mo plan (50k/month) or Amazon SES if usage grows.

5 · Digest + cron

5
StepPlan / notesTag
What each email saysMorning (~7:00 ET): followed companies reporting today, with before-open and after-close times, EPS and revenue estimates, and a link to the calendar. Evening (~7:00 PM ET): today's results (beat, mixed or miss, as on the calendar) and tomorrow's before-open reporters. If a user has nothing to report, send nothing.You listed
Cron routes/api/cron/digest?run=morning|evening, set in vercel.json. The route checks Authorization: Bearer $CRON_SECRET, refreshes today's and tomorrow's calendar from Finnhub first (ties in with "Scheduled Finnhub sync" on the features page), then builds and sends. Set maxDuration high enough for the batch.You listed
Time zones + DSTCron runs on UTC. 7:00 ET is 11:00 UTC in summer and 12:00 UTC in winter. Either accept a one-hour shift twice a year, or schedule both UTC hours and have the route skip the one that isn't 7 ET. On Hobby, Vercel runs a job at any point within the scheduled hour, so times are approximate.Limit
Send log (no doubles)Before sending, insert into notificationLog with _id = userId:date:run. If the insert fails as a duplicate, skip that user. Pass the same key to Resend as idempotencyKey. Retries and overlapping runs then can't send twice.Added
Date changesFinnhub dates move, and estimated dates become confirmed. Keep the date that was last emailed for each followed symbol, and add a "Date changed: NVDA moved to Nov 20" line to the next digest.Added

One-click unsubscribeEvery digest gets List-Unsubscribe and List-Unsubscribe-Post: List-Unsubscribe=One-Click headers, plus a footer link, both carrying a signed token (HMAC of the user ID), so unsubscribing works without signing in.
